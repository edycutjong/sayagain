# SayAgain evaluation protocol (pre-registered)

This file, `referee/aliases.py`, `referee/regex_extractor.py` and their tests are committed **before any language-model call on
recorded data** and tagged `prereg-v1`. The tag's commit timestamp is the pre-registration. Any later change to this file is a
visible diff against `prereg-v1`, listed in the "Deviations" section at the bottom with its reason.

Nothing in this file is a result. Every number below is a threshold, a target or a formula.

## 1. What is measured

One question: **when a field technician reads back a safety instruction wrongly, does SayAgain put it in front of a human, and how
many correct read-backs does it bother the human with?**

Verdicts per exchange: `VERIFIED`, `MISMATCH`, `NO_READBACK`, `ABSTAIN(reason)`, plus `NOT_AUDITED` when a model call failed
(rate limit, timeout). A `NOT_AUDITED` exchange stays in every denominator, is never counted as `VERIFIED` and never as flagged
(it reaches only the end-of-shift list, not the live queue), and is reported in its own column.

## 2. Corpus

Generated by `scripts/seed.py --seed 1018` (cards) and recorded by people, one WAV per card, file name = `exchange_id`.

| Set | Content | Badge |
|---|---|---|
| H | hero ("Close valve two-oh-three, line Bravo." → "Copy, closing two-oh-eight, line Bravo.") + secondary (read back "line Alpha") | `human·seeded` |
| R | the refusal: "Close valve two-oh-five, line Charlie." (XV-205 is not in the registry) | `human·seeded` |
| A2 | ≥ 100 exchanges, ≥ 50 seeded errors from `data/error_plan.csv` (wrong line 12, look-alike tag 14, wrong action 8, omitted field 6, no read-back 4, omitted command 4, uncorrected retraction 4; H counts inside these quotas), ≥ 50 correct; inside them ≥ 8 multi-command, ≥ 8 spoken corrections, ≥ 6 say-again sequences, 6–8 caught-on-channel exchanges | `human·seeded` or `human·seeded·1-voice` |
| C | 20–30 chatter turns (no instruction), 3 of them contain clock times | same |
| KT | 20 kill-test exchanges in the builder's own voice (10 English, 10 code-switched) | `human·seeded·1-voice` |
| X | 10–20 instructions phrased by someone else, written down **before** alias tuning | reported as a separate row |

Labels come from the card (what the speaker was asked to say). If a speaker departs from the card, the label is corrected **by
listening**, before any model output on that clip is looked at, and the correction is logged in `data/label-fixes.csv`.

Radio path: `scripts/radioize.py` (300–3400 Hz band-pass, μ-law 8 kHz round-trip, squelch tail) → badge `radio·simulated`.
SNR = 20·log10(speech level ÷ noise RMS), speech level = RMS over the frames within 35 dB of the loudest frame (silences
excluded). Noise: `scripts/mix.py --seed 1018` at clean / +6 / 0 / −6 dB SNR with MIMII pump / valve / fan recordings (CC BY-SA 4.0, eval
only, never committed). The four SNR copies of one exchange are the same speech: each SNR is its own row, never pooled.

### Dev slice

Aliases, the ASR prompt and the coverage rules may be tuned **only** on the dev slice: the 20 KT exchanges + the first 20 A2
exchanges in card order (`A2-001` … `A2-020`). They are then frozen by the git tag `aliases-frozen-v1`. Every headline number is
scored on the rest of A2 with the frozen code; the dev slice is reported as its own row and never mixed into the headline.

## 3. Pipeline under test

audio → VAD turns → ASR → extractor (rung) → referee (grounding → coverage → aliases → registry precedence → pairing → audio
gate → verdict). The referee is the same code for every rung. Receipts record, per call: stage, endpoint host, model id,
request id, timings, `on_amd` (the endpoint is AMD-operated — it does not name a GPU), and for ASR the language token and
the prompt.

### Audio gate

* If the ASR route returns per-token log-probabilities: `span_conf` = the minimum token probability inside the action, tag and line
  spans of both utterances. The floor is set by **2-fold cross-fitting** on A2 (folds by `exchange_id`, so all SNR copies of an
  exchange share a fold): for each fold k, the floor is fitted on the other fold as the lowest value at which that fold has
  0 false-VERIFIED, then applied to fold k. The headline is the pooled out-of-fold result on all of A2 (minus the dev slice).
* If it does not (expected on a hosted API): the **disagreement gate** — ASR runs twice, with and without the vocabulary prompt;
  the frozen regex + alias extractor reads the canonical (action, tag, line) from both transcripts; any difference →
  `ABSTAIN(audio)`. If the ASR route does not accept a prompt, the receipts and README state "no audio gate".

## 4. Metrics (formulas are fixed here)

* **Errors flagged** = (MISMATCH + NO_READBACK + ABSTAIN on seeded-error exchanges) ÷ seeded-error exchanges.
  **MISMATCH-only recall** is reported beside it.
* **False-alarm load** = correct exchanges that reached the live queue (any non-VERIFIED verdict; spot-checks excluded) ÷ correct
  exchanges.
* **False-VERIFIED** = seeded-error exchanges that received `VERIFIED`. The safety number. Every one is listed with its clip.
* **Ungrounded rate** (model rungs only) = turns with `ABSTAIN(grounding)` ÷ turns with commands.
* **Abstain rate** per SNR row.
* **False cards per channel-hour** on the chatter set C = cards opened by chatter turns ÷ hours of chatter audio.
* **Precision reweighted to 1 % prevalence:** with recall `r` (errors flagged) and false-alarm load `f`,
  `P(1 %) = r · 0.01 / (r · 0.01 + f · 0.99)`. Printed next to the measured precision at the corpus prevalence.
* **Cards per supervisor-shift** = `f` × correct exchanges per shift + flagged errors per shift. Site assumption (labelled as an
  assumption everywhere): 6 channels × 30 instructions per channel per shift = 180 exchanges per shift.
* **Latency** per stage, p50 and p95: end of the read-back's speech (VAD timestamp) → verdict written; ASR and extraction
  timings from receipts.
* Every rate is reported with n and a **Wilson 95 % interval**.

## 5. Thresholds (decided now, before any result)

### Shift budget

Live budget: **15 cards per shift** (assumption, to be checked with a practitioner). Spot-checks (10 random VERIFIED per shift),
caught-on-channel exchanges and `NOT_AUDITED` exchanges go to the **end-of-shift list**, not the live budget. With ~2–5 real
errors per 180 exchanges, the live budget implies **false-alarm load ≤ 5 %**.

### Headline targets (0 dB row, A2 minus dev slice)

| Metric | Target |
|---|---|
| Errors flagged | ≥ 90 % |
| False-alarm load | ≤ 5 % |
| False-VERIFIED | 0 (any non-zero is reported as a limitation with its clip) |

### Model ladder — the benchmark

* Rung 0 = `referee/regex_extractor.py` (no model). Rungs 1–3 = instruct models served by the AMD Token Factory, ordered by
  parameter count (smallest first), chosen from the `/models` list in `bench/results/access-gate.json`. **At most 4 rungs.**
* Same referee, same ASR transcripts, same prompt, temperature 0, thinking off, JSON-schema output.
* Per rung: false-VERIFIED, MISMATCH-only recall, errors flagged, false-alarm load, ungrounded rate (model rungs only — regex is
  grounded by construction), p50 / p95 extraction latency.
* **Headline = the smallest rung with 0 false-VERIFIED AND false-alarm load ≤ 5 %**, on the 0 dB row only.
* **If rung 0 (regex) meets the headline**, that is the reported result: no language model is needed on this corpus, and no
  claim says otherwise. The referee and the grounding self-ablation are then the reported contribution.

### Baselines and ablation

* `--ablate grounding`: the same model returns canonical values instead of spans; grounding and coverage are removed; same referee.
  Reported: false-VERIFIED with vs without the mechanism.
* `--baseline llm-judge`: the strongest Token Factory model is asked for a per-field structured verdict (action / tag / line
  match: yes / no) on the same transcripts. Reported: false-VERIFIED and false-alarm load.

### Kill test (local, before the AMD pipeline)

Whisper-large-v3 on the KT set, forced `en`, forced `id` and auto-detect, regex + aliases:

| Check | Pass if |
|---|---|
| Tag field exact match after alias normalisation, clean | ≥ 80 % |
| Tag field exact match at 0 dB | ≥ 60 % |
| Paired proxy: both utterances exact on tag + line, clean | ≥ 65 % |

Fail on code-switched only → pivot to English radio phraseology with Bahasa action words, re-test. Fail on both → stop; a human
decides.

### Blind auditor (business result)

Two shuffled sets at 10 % error prevalence: 2 × 40 (4 errors + 36 correct each) only if 72 distinct correct exchanges exist
(A2 + KT); else 2 × 30 (3 + 27), stated. Set 1 by ear with a stopwatch, set 2 through the SayAgain queue. Reported: minutes per
exchange, errors caught / missed, seconds from card shown to decision. n = 1 auditor, stated.

## 6. Reporting rules

* Every published number greps to a file in `bench/results/` or `evidence/` produced by a receipted run.
* Hardware, serving-stack and model names on any judged page render from receipts; a sentence that says a stage ran on AMD must
  map to a receipt stage with `*_on_amd = 1` (`scripts/check_submission_readiness.py` enforces it).
* Text-to-speech audio may appear only in unit-test fixtures, labelled `tts·fixture`, never in an eval row.
* Rows that were not run are printed as "not run", never dropped.
