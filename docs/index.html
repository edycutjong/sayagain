Model ladder · 89 held-out exchanges · text·scripted

Climb only as high as the rule needs.

The rule was pre-registered before the first model call, for the audio headline row (bench/PROTOCOL.md logs its use on these written-word rows as a deviation): the smallest rung with 0 false-VERIFIED (wrong read-backs passed) and at most 5 % false-alarm load (correct read-backs sent to a human). Every model rung extracts spans on the AMD Token Factory; the referee makes each one fail toward a human.

With so few cards the rates are wide: Gemma-4-31B-IT’s 2/48 is 4.17 % with a 95 % Wilson interval of 1.15 % to 13.98 % (bench/results/text/RESULTS.md). The baseline is DeepSeek-V4.1-Flash, a different model from the DeepSeek-V4-Flash rung.

On written words, rung 0 already meets the rule. A frozen regex, no model: 41/41 errors flagged, 0/48 false alarms. Whether that survives real speech, noise and other people’s phrasing is what the audio rows measure.

Grounding is load-bearing. The same model returning values instead of copied words: false alarms 2/48 → 6/48 (one more correct card not audited), in 4 of the 6 turning a spoken pump or motor-valve tag into a valve tag the registry does not have.

Judging is not the model’s job. Given the whole exchange and no registry, the LLM-as-judge baseline passed 2 wrong read-backs as VERIFIED and passed the XV-205 order, a valve the plant does not have.

Referee · one model job, everything else is code

The model points. Code decides. A human closes the card.

  1. 01

    The model points at words

    For each turn, the model on the AMD Token Factory returns the words that carry the action, the tag and the line: copied spans, never values. JSON mode, schema checked in code; a failed call is NOT_AUDITED, never a pass.

    0/194turns with a span not found in the transcript, Gemma-4-31B-IT, held-outcode: sayagain/extract.py

    {
  "commands": [
    {
      "action_span": "closing",
      "line_span": "line Bravo",
      "state_span": null,
      "tag_span": "two-oh-eight"
    }
  ],
  "kind": "readback",
  "retracted_spans": []
}

  2. 02

    The words must be there

    Every span must appear in the transcript, word for word.

    2/48 → 6/48false alarms when the same model returns values instead of copied words (one more card not audited)code: referee/grounding.py

  3. 03

    Every safety word counted

    A read-back that drops the action word, or keeps a line the operator retracted, cannot verify. A model that returns nothing usable sends the card to a human.

    48/48correct read-backs sent to a human when MiniCPM5-2B returned spans the referee could not ground or cover; none passedcode: referee/coverage.py

  4. 04

    The plant registry has the last word

    Spoken digits and NATO letters become tags through alias tables, and the tag must sit on the line the order names.

    120tags in the registry; XV-205 is not one of them, so its order is refuseddata: data/registry.csv

  5. 05

    A human closes every card

    Confirm, or dismiss with a reason. Nothing is ever sent to the plant.

    10random VERIFIED exchanges per shift go to an end-of-shift spot-checkcode: referee/audit.py

  6. 06

    The verdict is a pure function

    The verdict module imports no model code, and a test fails the build if it ever does.

    535tests collected by pytesttest: tests/test_verdict.py

Questions a judge would ask

FAQ

Where does the AMD Token Factory sit in the pipeline?

It does the one model job: span extraction. Each call returns the words for action, tag and line, and its receipt records the request id, the model served, the host and the cost.

Speech-to-text has not run on a recording yet; the Token Factory lists no transcription model. The referee and the queue are plain Python on the operator’s side.

Couldn’t an LLM just judge the read-back?

We measured that. DeepSeek-V4.1-Flash, given the whole exchange and no plant registry, passed 2 wrong read-backs as VERIFIED and passed the XV-205 order, a valve the plant does not have. In SayAgain the model only points at words; the verdict is code.

A regex already meets the rule. Why a model at all?

On clean written words it does: that is our own result, and the page says so. Real speech is not clean: recognition errors, code-switched Bahasa, other people’s phrasing. The audio rows decide whether a model earns its place; if they say it does not, the report will say that.

What happens when the radio is too noisy to hear?

On the written-word rows, a failed model call is NOT_AUDITED and an exchange the referee cannot clear reaches a human as ABSTAIN, in amber: listen yourself. How it behaves on noisy audio is not measured in this build; the −6 dB look-alike failure case needs the human recordings (no audio evaluation in this submission).

Does SayAgain control anything in the plant?

No. It has no write path to the plant. A card leaves the queue only when a supervisor confirms it or dismisses it with a reason.

Isn’t this a way to watch workers?

It is planned to check procedures, not people: the exchanges carry roles (operator, field tech), not names, and nothing scores a person. No audio has been processed yet. Voice that identifies a person is personal data under UU PDP 27/2022, so production is planned to run inside the company network, keeping audio only for cards in the queue.

Don’t radio loggers already do this?

They record and transcribe, and some spot keywords. Among the loggers we checked, none documents comparing an instruction with its read-back. Automatic read-back checking exists in air-traffic research (HAAWAII); we have not found it on plant radio.

Why is it called SayAgain?

“Say again” is the radio procedure word for “repeat that”. A wrong read-back deserves one; SayAgain makes sure somebody asks for it.

What on this page is real today?

Every verdict, trace, receipt and count comes from files in this repository: bench/results/, docs/replay/data/, evidence/. The exchanges are written scripts for a fictional plant (text·scripted); no recording has been measured. Dashed boxes are results that do not exist yet.
